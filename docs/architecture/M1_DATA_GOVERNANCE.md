# M1 data governance proposal

Status: PENDING_PARENT_REVIEW. Engineering policy acceptance does not clear external dataset distribution. No new canonical business/menu/transit records, raw OSM extracts, tiles, images or prior entity manifest were acquired or imported by M1 governance.

The High Street pilot is a project-defined engineering rectangle, independently serialized in `data/manifests/service-area-v1.json`. It intentionally uses the numeric M0 audit envelope for continuity while rejecting cadastral/district authority. It does not establish a business census, safe walkability or all-BGC coverage. The manifest defines inclusive edge membership, unsupported outside origins/destinations and a 200 m ingest-only buffer in EPSG:32651. M3 must materialize/review that metric buffer and preserve complete graph candidates across clipping edges; no unreviewed route excursion follows from having buffered data.

The source v1-to-v2 migration preserves the original 18 fields and appends five, including a distinct extractor version. Canonical register remains zero-row. M0 inventory remains historical; prior entity manifest and code are not reused. See `docs/data-source-register/README.md` and checksummed migration report. Stable source IDs identify a provider/source; immutable source snapshots identify particular bytes and acquisition. Name, URL edits or updated content never silently regenerate canonical IDs. SQL source snapshot/evidence/use-policy contracts are owned by the contracts lane.

Source gating has two separate stages:

1. **Bounded internal intake:** a reviewed raw OSM source under the public ODbL grant can support internal M3 engineering processing after acquisition-service policy review, actual bytes/checksum, extract version, retention and lineage metadata, and parent engineering approval. The helper requires an explicit `fresh_geofabrik` or `audited_prior_raw` mode. The latter permits only the two dated raw path/hash/provider tuples recorded below after current-byte, sidecar/license/origin/query/boundary verification and reference to independent M0 parent hash evidence. Another provider/snapshot requires a new explicit gate/review. `CANDIDATE` can remain appropriate while internal processing occurs. This gate does not require user distribution authorization and never makes the source/derived pack externally publishable. Acquisition authorization must be decided before downloading; the post-acquisition gate checks bytes before parse. No M1 dataset was downloaded.
2. **Offline export/distribution:** intended data/menu/image redistribution must each be positively granted. Require APPROVED source, exact acquired snapshot identity/hash, retained rights evidence, reviewer/date/expiry, approved offline retention/cache use, satisfied notices/obligations, parent engineering acceptance, human rights review and explicit user distribution authorization. Missing, false, UNKNOWN, stale or revoked required rights deny export. Engineering implementation cannot supply a legal decision. Public OSMF raster offline use is categorically denied even if review booleans incorrectly claim approval. Public access to merchant material never supplies a menu/photo license.

The gates return denial reasons and have no download/export side effects. Test fixtures marked TEST ONLY demonstrate behavior; no real source is cleared. Actual release pipelines must retain the concrete decision evidence, compare snapshot identity and re-evaluate expiration/current terms at export time. Do not convert any engineering helper result into a license certificate.

The [OSM copyright page](https://www.openstreetmap.org/copyright) identifies ODbL data and attribution obligations. The [ODbL legal code](https://opendatacommons.org/licenses/odbl/1-0/) addresses notices, derivative/collective databases and share alike; it does not independently license every image or other content. The pack's actual transformations, database arrangement, license notices and any required database/alteration offer need human review before distribution. Separate merchant tables improve lineage but do not themselves settle derivative-database classification.

The [OSMF raster policy](https://operations.osmfoundation.org/policies/tiles/) prohibits offline/prefetch use of its standard public raster service. Use reviewed self-generated resources from licensed raw data or a provider explicitly permitting offline use. Production style, glyphs, sprites, fonts and imagery each need separate rights and offline validation; ODbL does not grant those asset licenses. [OSMF attribution guidance](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines) informs visible map credit and offline-accessible notices; M1 has not tested production attribution UI. [Geofabrik Philippines](https://download.geofabrik.de/asia/philippines.html) is a raw-data lead; no PBF acquired here.
