# M1 canonical contract (proposed; parent acceptance pending)

Canonical IDs are random immutable lowercase UUIDs generated once at intake. They are not derived from names, coordinates, external IDs or file ordering. Global entity identity distinguishes a physical building, business operator, branch/tenant place, and physical entrance. A branch can share a business with another branch; different floors and doors retain separate IDs. Source identifiers and legacy IDs are scoped external references, never canonical replacements. Duplicate candidates are reviewed rather than merged; an explicit redirect audit is needed for a future merge.

All factual values live in the fact ledger, with property, explicit knowledge state, review/freshness/location state, temporal bounds and evidence links. Unknown, absent, not applicable and asserted values are distinct; unknown menu data cannot mean no menu. Approved identity alone never clears an individual fact or source. Source rights are separately tracked for offline caching, redistribution and attribution. Unknown rights fail closed. Null floor means unknown, not ground floor; floor labels belong to a building.

Staging schema and mobile distribution schema are separate versioned SQLite databases. Export is a deterministic local proposal, never authorization to publish. Only approved, current, unambiguous entities and matching current approved facts with supporting current approved evidence, approved sources and explicit rights/attribution enter an export. Pending/stale/conflicting evidence is not positive support. Source and extract versions are separate. Source checksums refer to exact snapshots; synthetic test data is never a real BGC inventory.

WGS84 uses longitude then latitude; metric lengths cannot use angular differences. See packages/geo. Native connection ownership and hidden Expo workaround are documented in packages/database/NATIVE_LIFECYCLE.md. Desktop SQLite tests do not prove Android/iOS readiness.
