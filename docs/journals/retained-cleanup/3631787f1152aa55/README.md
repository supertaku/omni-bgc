## Scope and implementation

`apps/mobile/src/qa/ai-evaluation/` contains the isolated fixture lane, actual provider/executor trace decorators, runner, receipt gates, bounded SAF input/export, and internal screen. `AgentOrchestrator` adds one optional trusted-adapter untrusted-source observation group, ordinary user role, maximum1024characters, within existing UTF-8 transcript budgets. It adds no tool, round, call, source-approval or write capability.

The existing conversation owner lends its already verified READY provider. A separate lease survives Stop/background and blocks send, clear, model operations, new evaluation and export until the runner settles, positive native idle is observed and the sink is closed. Unknown idle keeps the lease locked; restart is required. A positively idle poisoned provider can remain unavailable without being marked READY. No second runtime/history store, production database write, source promotion or coordinate is created.

The native candidate adds only exact-preview-package read APIs for own APK SHA256 and memory/thermal metadata. The provider exposes only the identity of its already loaded verified model. These changes require explicit current-native-manifest review and an Android build; they have not been compiled or device-tested here. Preserve original R4 artifacts and recovered-source inventory.

Normal builds force `EXPO_PUBLIC_AI_EVALUATION=0`. Only explicit builder `--enable-evaluation-harness` sets1 and records it in source receipt and APK verification. Later phases reject a flag differing from the frozen stage. The hidden entry also checks exact package `com.omnibgc.aipreview`. Native helpers are read-only package-gated code; the flag disables the JavaScript evaluation flow, not a claim that every QA symbol is stripped from the binary.

## Review and integration sequence

1. Inspect `integration.patch`, source checksums and baseline/rebase receipts. Parent explicitly ACCEPTS before integration. Resolve the two UI files as merges; do not restore stale normal UI.
2. Update the **current** native manifest entry only after reviewing the read-only Kotlin diff. Enroll new QA TS/TSX files in authored formatting, and add the three regression files to the host quality runner. The source builder candidate freezes the two new host helper scripts as authored inputs.
3. Generate inputs with pinned local tools: `node scripts/prepare-ai-device-evaluation.cjs SOURCE_ROOT OUTPUT_ROOT`. For an integrated tree both roots are the repository; the manifest goes to `docs/evaluations/offline-ai/D4_INPUT_MANIFEST.json`. Original private copies are made only when output differs from source. Do not run the historical private `make-integration-candidates.cjs` against newer UI; it intentionally rejects base drift.
4. Run appropriate full source/host gates, then build a fresh isolated stage with `--enable-evaluation-harness`. A normal build without that switch stays disabled even if the shell inherits flag1. Independently audit APK, permissions/certificate, JNI/DEX, source ZIP/receipts/maps, and native test XML before device use.
5. After the new APK exists, create a host envelope using `node scripts/create-ai-device-evaluation-receipt.cjs APK SOURCE_RECEIPT APK_VERIFICATION MODEL_SOURCE_RECEIPT INPUT_MANIFEST OUTPUT RUN_ID`. It hashes actual APK/source/verifier bytes, requires the verifier's exact success/package/QA flag and APK/source joins, and checks frozen input/scope rows. A unique output is created with no overwrite. This avoids embedding the final APK/source-receipt digest into itself.
6. The owner uses the hidden internal entry, imports the bounded envelope through SAF and explicitly confirms Start. The phone rehashes both raw provenance documents, checks frozen input/scope associations, hashes its own base APK and checks loaded model identity. These are **operator-supplied consistency associations, not signatures or authenticated source attestation**. Reviewers still inspect the host artifact chain.
7. Keep parent-owned external device evidence/health monitoring. The runner samples PSS/free memory/thermal before/between cases and once per second during a case, uses existing turn/native cancellation deadlines, and yields between rows. Those samples are not a frame/energy benchmark or instantaneous resource guarantee. Lifecycle/resource failures stop remaining cases as unrun; an invalid proposal alone may continue if actual provider/health remain safe.
8. Export only after the lease settles. Explicit SAF folder choice writes only this run trace and sidecar; source/export trace SHA256 and sidecar readback SHA256 are checked. The sidecar hash is displayed for independent host comparison. No broad storage permission or release `run-as` assumption is used. Preserve the private source trace on export failure. File writes are not a claim of fsync/crash durability.
