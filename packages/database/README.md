# M1 SQLite schemas — proposed, pending parent review

`migrations/staging/001_initial.up.sql` is the normalized editing contract. `migrations/mobile/001_initial.up.sql` is a separate compact fact/identity/point/citation/search contract. Neither modifies the M0 native spike. The exporter is deliberately bounded to identity, approved facts, WGS84 points and FTS names/aliases/menu text; graph topology, polygon packs, transit scheduling and local saved-history APIs require later owned migrations and validation. Staging contains those normalized entities now, without invented content. Saved records must use a separate platform-private user database; do not include them in source distributions.

Run `python -m unittest discover -s tests/data-quality/m1 -p "test_*.py" -v`. Foreign keys are connection-local and mandatory; the exporter checks them. Migrations execute in explicit transactions; down migrations are disposable-empty-schema development rollback only and cannot undo source/ID changes. Production pack rollback retains the previous validated file; destructive down migrations are forbidden on sole user data. Schema versions are explicit, existing IDs are immutable, and any change requires a new migration and parent review.

Source registry fields mirror governance v2's23 fields. SQL distinguishes immutable snapshot identity and independently reviewed use policy from registry metadata. Source CSV UNKNOWN becomes SQL UNKNOWN, not consent. Internal raw OSM ingest review does not authorize export: export additionally requires rights review, satisfied obligations and user distribution authorization. Public OSMF raster sources are categorically denied. Policy's raw SHA256 binds rights to one extract; do not copy rights to another snapshot. Export reports rejected entity/fact counts; it is local proposed tooling, not a publishing operation. Null or expired policy/review metadata blocks export. No acquired/approved BGC facts are bundled.

Policies are keyed by exact immutable snapshot UUID and intended use (`data` or `menu_text`), with matching source/checksum. Menu facts require the menu_text use policy and explicit menu-text permission. Parent links require their own approved relationship facts; an approved name cannot authorize a branch/building association. The staging FTS index includes candidates for reviewer lookup and MUST NOT be used directly by the mobile user interface. Compact mobile search indexes only exported names, aliases and descriptions. Taxonomy v1 is proposed and contains15 explicit hierarchical codes; a future taxonomy change requires reviewed version/migration. Fact IDs, subject/property, source IDs and snapshot lineage cannot be rewritten silently.
