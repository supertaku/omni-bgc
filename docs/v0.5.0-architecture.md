# The Fort v0.5.0 architecture decisions

Baseline: `a8e1546`, initially clean. Implementation uses local branch `codex/the-fort-v050`.

Retain Expo/React Native, MapLibre 11.5, SQLite FTS/RTree, deterministic retrieval,
LiteRT-LM and its native ownership/cancellation/release fences. Retain both original
checksum-bound map packs, app identity, migrations, verified downloads and history.
The supplied master plan is the implementation brief; no public deployment is authorized.

- Map: keep one native map. Serialize style revisions using native style/render events;
  camera operations depend on the installed revision. Flat and illustrated styles share
  source geometry and use versioned presentation metadata. Source heights remain separate
  from illustrative styling. Clusters keep expansion/list access without numbered badges.
- Coverage: retain the reviewed service polygon as evidence. Generate a separate 100 m
  UTM 51N render buffer and digest manifest. Rendering coverage grants no business approval
  or pedestrian navigation eligibility. Source gaps remain listed, never filled with
  fictional footprints. Retain the existing Python pipeline unless a concrete blocker
  justifies Planetiler.
- Selection: Application owns selected place and highlighted result IDs. Assistant payloads
  reference canonical IDs; fresh results populate highlights and explicit map actions
  re-resolve current approved records. Records lacking eligible coordinates remain text.
- Location: move controls to the map. Foreground GPS is requested only by a tap; positioning
  stays in session and on device. Manual origins remain available on the map. No route UI.
- Directory/evidence: extend existing Place/Citation/Entrance and approved parent relations;
  retain source filters, exact PHP evidence and the distinction between candidates and
  approved businesses. No bulk directory import without review and reuse rights.
- Models: extend the existing verified catalog and installer, preserve Gemma. Candidate
  artifact identity and native runtime acceptance are separate. Severe Android thermal
  status is never bypassed; recovery is explicit and never replays a prompt.
- Packs/navigation: keep the existing transactional, digest-checked installer and empty
  approved catalog. Keep pedestrian topology separate from decorative map features;
  full walking navigation remains deferred.

Implementation agents own map lifecycle/presentation, coverage/resources, and models/native
AI respectively. The parent owns Application, discovery selection, UI/brand and release.
No root README rewrite or development journal is introduced. Final integration uses focused
host checks, Expo prebuild and Gradle ARM64 release; phone rendering/crash/inference/thermal
acceptance is explicitly left to the owner, without USB/ADB activity.
